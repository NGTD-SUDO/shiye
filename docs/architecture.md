# 架构说明

## 一句话

三端一库：Flutter 客户端（手机 + 桌面）→ FastAPI 后端 → SQLite（元数据 + OCR 文本 + FTS 索引），图片落磁盘，OCR 与 AI 都是可替换的适配器。

## 架构图

```
┌─────────────────────┐   HTTPS   ┌──────────────────────────────────┐
│ 手机端 (Flutter)      │◄────────►│ 后端 (FastAPI)                    │
│ 拍照/裁剪/归档/搜索    │          │ ├─ REST API (JWT)                 │
└─────────────────────┘          │ ├─ OCR 任务队列 (异步 worker)       │
                                 │ ├─ SQLite：元数据 + OCR 文本 + FTS │
┌─────────────────────┐          │ ├─ 图片存储（磁盘，可换 OSS）        │
│ 电脑端 (Flutter Win)  │◄────────►│ └─ OcrProvider 抽象层              │
│ 批量导入/校对/导出     │          │      ├─ 百度手写识别 API（默认）    │
└─────────────────────┘          │      └─ RapidOCR 自部署（离线/隐私） │
                                 │ AI：DeepSeek（单次轻请求，可换兼容服务）│
                                 └──────────────────────────────────┘
```

## 核心数据流

```
拍照/选图 → 客户端裁剪+压缩 → 上传(选学科) → 服务端存图 + 建页记录 + 投递 OCR 任务
   → OCR 识别（pending→processing→done/failed）→ 文本写回记录 → 文本进 FTS 索引
   → 用户搜索命中 → 看原图 / 校对修正文本（修正也回写索引，搜索立即变准）
```

## 目录结构

```
backend/app/
  main.py            应用装配、路由挂载、启动时补投未完成 OCR
  config.py          全部配置从环境变量读（含生产强校验：SECRET_KEY / DEV_MODE）
  models/            SQLAlchemy 模型
  routers/           各资源的 HTTP 接口
  services/          业务逻辑（归档、搜索、导出、学情、判分…）
  ocr/               OcrProvider 抽象 + baidu_impl / rapidocr_impl
  ai/                AI 提供方抽象（DeepSeek 实现）
  legal_content.py   法律文档生成（邮箱写成 HTML 实体，防中间层改写）
  storage/           图片落盘目录（运行时生成，不入库）
frontend/lib/
  core/              API 客户端、模型、主题、通用组件
  features/          按功能分目录：auth / subjects / pages / search / review / study / legal …
```

## 关键决策（以及为什么）

| 决策 | 理由 |
|---|---|
| **OCR 放服务端，不放手机端** | 中文手写没有好用的端侧离线模型；放服务端顺带统一图片存储与检索 |
| **识别文本可人工修正，且修正写回 FTS** | 「接受识别不完美」的落点，没这条闭环产品不可信 |
| **OCR / AI 都做抽象接口** | 隐私优先可切 RapidOCR、成本优先可切云 API，不动上层 |
| **SQLite + FTS5** | 个人到家庭量级足够，零运维；中文子串匹配用 trigram |
| **AI 只做「一次请求一个结果」** | 学情分析 / 章节整理；不做多轮对话、不做向量库 RAG、不做订阅体系 |
| **AI 只发必要文本** | 统计数字 + 学科/页标题，不发图片、不发全文，控制成本与隐私面 |
| **数据太少时出真实空态** | 不编造统计、不硬出报告（宁可空着） |
| **「同意前零采集」** | 客户端未点「同意」前不触发任何认证/上报，有测试钉住调用次数为 0 |
| **配置全走环境变量，含生产强校验** | `SHIYE_DEV_MODE=false` 时 `SECRET_KEY` 为空/默认值/短于 32 位直接拒绝启动 |

## 数据模型（概览）

`users` → `subjects`（学科）→ `chapters`（章）→ `pages`（页，含图片路径、OCR 文本、OCR 状态、置信度）→ `quiz / study_report`（出题与学情）等。
整章 AI 整理结果单独落库，用于**避免同章重复调用 AI**。

## 前端约定

- 主题令牌集中在 `features/*/theme` 与设计令牌文件，禁止散落硬编码色值
- 触控目标 ≥44px；三级文字对比度满足可读性要求
- 客户端**不硬编码任何服务地址**，一律 `--dart-define=API_BASE_URL=...` 注入
